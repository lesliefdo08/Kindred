# Windows Signing Readiness

## Current State

- `app.setAppUserModelId("com.kindred.ide")` is set before any window is created in `electron/main.ts`.
- `build.win.signAndEditExecutable` is `false`, so the executable is edited in `afterPack` before signing instead of after signing.
- `build.nsis.installerIcon`, `uninstallerIcon`, and `installerHeaderIcon` are already set to `kindred_logo.ico`.
- `packElevateHelper` is disabled, which removes the unsigned `resources\elevate.exe` helper from the packaged payload.
- The installer and uninstaller remain signable by electron-builder once a certificate is provided.

## Signing Readiness Checklist

- Use a valid Authenticode certificate for `Kindred Setup.exe` and `Kindred.exe`.
- Keep all executable mutations before signing only.
- Do not add any post-signing resource edits.
- Keep the installer/uninstaller generated by electron-builder so both can be signed in the standard flow.
- Keep `app.setAppUserModelId("com.kindred.ide")` unchanged for Windows identity.
- Keep `packElevateHelper` disabled unless a per-machine installer is required.
- Verify Smart App Control behavior with the signed installer on a clean machine.

## Standard Authenticode Commands

### PFX certificate file

```powershell
$env:CSC_LINK = 'C:\signing\Kindred.pfx'
$env:CSC_KEY_PASSWORD = 'your-pfx-password'
npm run dist:win
```

### Alternative environment names supported by electron-builder

```powershell
$env:WIN_CSC_LINK = 'C:\signing\Kindred.pfx'
$env:WIN_CSC_KEY_PASSWORD = 'your-pfx-password'
npm run dist:win
```

## EV Certificate Path

For future EV support, keep the build command the same and point electron-builder at the EV certificate source you use:

- hardware token + vendor signing tool
- Windows certificate store subject or SHA1 selection
- cloud signing service / remote signing agent

Recommended approach:

- prefer store-based selection by subject or SHA1 when the cert is installed on the signing machine
- keep all resource edits before signing
- avoid modifying `Kindred.exe` after electron-builder signs it

## Signature Verification Targets

After signing, verify these artifacts:

- `release\Kindred Setup.exe`
- `release\win-unpacked\Kindred.exe`
- installed `Kindred.exe`
- installed `Uninstall Kindred.exe`

Also confirm the package no longer ships `resources\elevate.exe` unless per-machine elevation is intentionally re-enabled.

## Smart App Control Notes

- Unsigned installers are the primary Smart App Control risk.
- Packaging artifacts that are modified after signing can also trigger reputation issues.
- Keep the build deterministic and avoid adding temporary executables or postinstall-generated runtime helpers to the release payload.
